兼容策略：

兼容性反例

依据当前旧、新两份 Schema，自动搜索一条旧版校验通过、新版校验拒绝的 JSON 实例， 无需先准备存量数据即可直接复现升级破坏。搜索会遍历对象选填字段、enum 的后续取值与 整数 / 字符串 / 数组的边界值；旧、新 Schema 各由独立 Ajv（draft-07）实例编译，每个候选都经两版完整复验， 最多检查 500 个旧版合法候选。

支持：文档内本地 $ref、布尔 Schema、单一 type、对象 properties/required、 const/enum、数组单一 items/minItems、minLength、整数上下界

有效样本生成（接口联调）

从当前旧 / 新 Schema 中选一份，生成一个最小合法 JSON 实例：对象只填必填字段、数组取最少元素、 字符串用 a 补足长度、整数取范围内最接近零的值、enum 按顺序尝试。 结果经 Ajv（draft-07）复验通过后才显示。 


      

    


    
    

      

        
存量实例迁移核验

        

          粘贴一个由存量 JSON 实例组成的数组（最多 100 条），服务端用 Ajv（draft-07）分别按当前旧、新两份
          Schema 逐条校验，按「新旧均通过 / 仅旧版通过 / 仅新版通过 / 两版均失败」汇总，顺序与输入一致。
          「仅旧版通过」即升级后会被新版拒收的存量数据。错误位置使用 JSON Pointer，
          缺失必填项与多余属性定位到具体字段；仅解析文档内本地 $ref，不会获取远程引用。
